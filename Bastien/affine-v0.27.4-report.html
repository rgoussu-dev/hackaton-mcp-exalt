Breaking changes

La fonctionnalité BYOK (Bring-Your-Own-Key) pour les fournisseurs IA reste expérimentale et peut nécessiter une reconfiguration lors de la mise à jour. Nouveau dans les notes de la v0.27.4 (absent de la v0.27.3) ; sous-tendu par le travail de refonte BYOK/legacy-compat de ce cycle.
Notes de release v0.27.4 ; PR #15426 (feat(server): converge legacy compatibility), PR #15427 (feat(core): improve byok editing), PR #15448 (feat(server): improve context management)
Vérifier, et reconfigurer si nécessaire, les fournisseurs BYOK après la mise à jour.
Reporté depuis les releases précédentes (inchangé en v0.27.4) : la compatibilité de protocole client/serveur est verrouillée — un serveur en v0.27+ n'accepte que des clients en v0.26+, et un client en v0.27+ exige un serveur en v0.27+.
Notes de release v0.27.4 et v0.27.3 (formulation identique)
Mettre à jour serveur auto-hébergé et clients ensemble, en respectant ce plancher de version.
Reporté depuis les releases précédentes (inchangé en v0.27.4) : depuis la v0.27 serveur, les variables d'environnement ne sont plus la source de configuration privilégiée et certaines ont été supprimées au profit de config.json.
Notes de release v0.27.4 et v0.27.3 (formulation identique)
Migrer la configuration auto-hébergée vers config.json — voir https://docs.affine.pro/self-host-affine/install/configuration

Méthodologie & hypothèses

Données récupérées via le serveur MCP GitHub. Règles de classification issues d'AGENTS.md / SKILL.md du dépôt cible lorsqu'ils existent, sinon des heuristiques par défaut de l'agent github-release-report.

  • Aucun AGENTS.md n'a été trouvé à la racine (ni dans .github/ ou docs/) de toeverything/AFFiNE ; une recherche floue n'a fait correspondre qu'un AGENTS.md sans rapport, situé dans packages/frontend/apps/ios/. Les heuristiques par défaut (section 5 du prompt agent) ont été utilisées pour la détection des breaking changes, le mapping de composants, la détection des bots, les manifestes de dépendances et la politique de pré-releases.
  • La release précédente retenue est v0.27.3 (publiée le 2026-07-23), la release non-pré-release et non-draft la plus proche avant v0.27.4 (publiée le 2026-08-18). Les pré-releases canary/beta intercalées (par ex. v0.27.5-beta.1 et plusieurs tags v2026.x.x-canary.*) ont été exclues conformément à la politique par défaut.
  • L'attribution par composant utilise les labels de PR propres au dépôt AFFiNE (app:server, app:electron, app:core, mod:native, mod:server-native, mod:i18n, mod:infra, mod:dev, mod:component, dependencies, rust, test, docs) plutôt qu'une heuristique par dossier, car les PR de ce monorepo touchent couramment des fichiers dans de nombreux dossiers. Quand une PR porte plusieurs de ces labels, un ordre de priorité fixe (server > electron > core > native > server-native > i18n > infra > dev > component > dependencies > rust > test > docs > other) détermine un composant principal unique, ce qui peut sous-compter des zones secondaires également touchées.
  • Le délai d'approbation des PR n'est pertinent que pour les 5 PR de contributeurs externes non-mainteneurs (#15381, #15412, #15436, #15461, #15478), chacune ayant nécessité une revue humaine explicite APPROVED du mainteneur (darkskygit) avant fusion. Les 50 autres PR (30 de darkskygit lui-même, plus 25 PR renovate[bot]) ont été auto-fusionnées avec uniquement des commentaires automatisés de CodeRabbit, sans événement d'approbation humaine distinct ; leur délai est donc marqué "non disponible" et exclu de la moyenne/médiane.
  • Le marqueur "assistée par agent" suit l'heuristique par défaut : vrai pour les 25 PR de renovate[bot], plus la PR #15478 dont la description contient une mention explicite "Generated with Claude Code". coderabbitai[bot] n'apparaît que comme relecteur/commentateur automatisé sur presque toutes les PR, jamais comme auteur, et ne déclenche donc pas ce marqueur à lui seul.
  • Les totaux de lignes pour deux grosses PR de dépendances portant uniquement sur des lockfiles (#15443 mermaid, #15457 second bump nestjs) sont approximatifs, comptés manuellement à partir des hunks de diff unifié renvoyés par l'outil MCP, faute d'un total agrégé unique pour ces entrées.
  • build_stats est indisponible : aucun outil MCP GitHub exposant les workflow runs / jobs CI n'était disponible dans cette session ; les statistiques de build sont donc omises conformément à la règle de non-invention de métriques.
  • Le changelog liste individuellement les 30 PR hors dépendances (features/fixes/chores) ainsi que les 5 mises à jour de dépendances signalées [SECURITY] ; les ~20 autres mises à jour de dépendances routinières de renovate[bot] sont regroupées en une seule entrée "Autres" et détaillées individuellement dans la section Dépendances.

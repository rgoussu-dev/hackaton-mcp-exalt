Résumé exécutif

rgoussu-dev est un profil très actif, principalement concentré sur le projet personnel Keel. Les résultats MCP consultés retournent 10 repositories publics, 99 commits et 127 PR, dont 94 associées à Keel.

Les contributions couvrent les CLI, le scaffolding multi-stack, les architectures modulaires, les tests E2E, Playwright, Docker et les outils agentiques. Les descriptions de PR sont souvent détaillées et accompagnées de plans de test.

Les checks CI vérifiés sont entièrement réussis pour les PR #153, #118 et #126. La reconnaissance externe reste toutefois limitée : les repositories personnels observés ont zéro étoile et zéro fork, et les reviews humaines indépendantes sont peu visibles.

Points de vigilance

  • Reconnaissance mesurable faible : zéro étoile et zéro fork sur les repositories observés.
  • Peu de preuves de contributions externes à des projets tiers.
  • Reviews humaines indépendantes peu visibles.
  • Certaines validations importantes sont annoncées comme restant à exécuter localement.

Questions d'entretien personnalisées

  1. PR #153 : comment séparer les métriques universelles d'un runner des métriques propres à chaque agent ? Évalue la conception d'abstraction.
  2. PR #153 : comment garantir qu'un timeout ne laisse aucun processus enfant orphelin ? Évalue la robustesse opérationnelle.
  3. PR #118 : pourquoi démarrer le vrai binaire CLI plutôt que tester le serveur en mémoire ? Évalue la compréhension des tests d'intégration.
  4. PR #118 : quels problèmes apparaissent lorsqu'un composant remplace son sous-arbre DOM pendant une interaction asynchrone ? Évalue la compréhension des courses frontend.
  5. Issue #25 : pourquoi placer le contrat REST à la frontière frontend/backend ? Évalue la conception d'API.
  6. Issue #25 : quels compromis entre images multi-stage, développement local et reproductibilité CI ? Évalue la conteneurisation.
  7. Projet Keel : quand une nouvelle stack doit-elle entrer dans le générateur plutôt que rester une expérimentation ? Évalue la gestion de la complexité.

Conclusion prudente

Le profil présente une expertise apparente dans les outils développeur, les CLI, les générateurs multi-stack, les systèmes de test et les intégrations agentiques. Il pourrait être pertinent pour des environnements developer tooling, plateforme, architecture logicielle, DX, automatisation ou prototypage avancé.

À valider en entretien : compréhension personnelle des contributions assistées par IA, expérience de collaboration externe, gestion de la dette technique, robustesse réelle des fonctionnalités et capacité de maintenance.

Limites : les métriques GitHub ne mesurent pas le travail privé, les compétences humaines, l'ensemble de l'expérience ni l'aptitude globale à occuper un poste.

Cette analyse repose uniquement sur des données GitHub publiques. Elle ne mesure pas les compétences privées, l'ensemble de l'expérience professionnelle, la personnalité ou l'aptitude globale à occuper un poste. Elle doit être utilisée comme support de discussion et non comme décision automatisée de recrutement.
